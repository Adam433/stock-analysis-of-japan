# Epic 6 Retrospective

## 1. Epic Review

### What Worked

- Epic 6 的两条故事目标清晰互补：6.1 统一前端信任/无障碍/错误状态信号，6.2 锁紧后端安全与未来扩展边界，前后端硬化一次成型。
- 6.1 复用了已有的 `marketDataHealth` 信号，通过共享 `WorkflowTrustBanner` 把 screen、stock-detail、watchlist、backtest 四个主工作流的“可信/陈旧/不可用”语义统一，而不是各路由自行发明文案。
- 6.2 把原本只写在架构文档里的“provider 仅后端、仅日本市场”约束，下沉到代码层（provider 元数据 + registry 拒绝越界 + ingestion job 走 registry），并用 `test_security_boundaries` 把规则固化为可回归测试。
- 去掉 workflow 路由中的 `NEXT_PUBLIC_*` 回退，把 API base 配置留在服务端，避免后续 broker/多市场扩展时凭证误泄到浏览器层。
- 通过 ADR `docs/adr/0001-mvp-research-boundaries.md` 把“MVP 只做日股 EOD 研究、broker/多市场是加法扩展”写成有坐标的决策，后续扩展不再只能靠口头共识。

### What Was Hard

- 硬化类工作天然容易发散。需要不断把范围收回到两条 AC（显式状态文案、键盘可达 + 非颜色依赖），否则会滑向无止境的 UI 打磨。
- 信任状态的语义边界需要显式拆分：error / invalid input / stale data / partial data 不能被压缩成单一“失败”语言，Banner 的 variant 需要和实际 health 信号对齐。
- 前端目前仍然只用 lint + build 做兜底，没有针对 Banner 与焦点样式的专门组件测试，行为回归依赖人工核对。

### Lessons Learned

- 可信性信号一旦要跨工作流一致，就应该抽共享组件而不是每条路由各写一份文案——Banner 的抽取显著降低了“下次新工作流忘记接 health 信号”的风险。
- 架构边界（谁是后端-only、哪些市场在 MVP 内）最好同时以三种形态存在：代码中的 registry 守卫、测试中的断言、ADR 中的文字说明。任何一层缺失都容易被未来改动悄悄绕过。
- 无障碍硬化应在功能稳定期集中做一次，比把它摊进每个特性故事更高效，因为焦点样式、ARIA 标注、状态语义有强共性。

### Technical Debt / Follow-Up

- 前端仍缺失对 `WorkflowTrustBanner` 和表单无效态/状态消息的组件级自动化测试，目前只靠 `npm run lint` 与 `npm run build`。
- 键盘可达性只做了人工审计和 CSS 焦点可见化，没有引入 axe / Playwright 的自动无障碍回归。
- Provider registry 目前只覆盖日股 EOD 静态 provider；当第一个真实外部 provider 接入时，需要补“未注册 provider 被拒绝”的端到端路径测试。
- ADR 0001 以外还没有补充对“broker 集成何时从研究工作流分离”的更细设计，等到第一次 post-MVP 扩展再补即可。

## 2. Next Epic Preparation

Epic 6 是 MVP 的收口 Epic，后续不再有计划中的 Epic。下一阶段的建议观察项：

### Ready Signals

- 所有主工作流（screen / stock-detail / watchlist / backtest）都挂上了统一的信任状态显示。
- 后端 provider 边界已进入代码层并有回归测试，可以作为未来 broker/多市场扩展的锚点。
- ADR 0001 为任何 post-MVP 扩展提供了明确的“不可静默扩大 MVP provider 契约”约束。

### Risks to Watch

- 未来增加真实外部 provider 时，若不扩展 registry 元数据（市场/凭证边界），AC1 的保障会弱化。
- 前端无障碍目前靠人工 + CSS，后续如果换 UI 框架或新增复杂交互（拖拽、弹层），需要重新审计键盘可达性。
- Trust banner 文案一致性依赖所有新路由都挂载组件；如果后续绕过共享组件，会复现“每个路由自造文案”的老问题。

### Action Items

- 在后续任一 UI 重构 PR 中，加一条最小组件测试覆盖 `WorkflowTrustBanner` 的三种 variant 渲染。
- 第一次接入真实 provider 时，补端到端测试验证 registry 拒绝越界 provider，并在 ADR 中追加决策条目。
- 如果后续启动 Epic 7+，把“新工作流必须挂载 WorkflowTrustBanner + 通过键盘审计”写进故事 Definition of Done。
