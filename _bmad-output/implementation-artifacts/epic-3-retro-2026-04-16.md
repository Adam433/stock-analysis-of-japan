# Epic 3 Retrospective

## 1. Epic Review

### What Worked

- Epic 3 kept the stock-detail flow anchored to persisted `screen_run` facts instead of ad hoc current-state calculations.
- Moving from payload service to explainable UI in small steps helped preserve trust: chart data, rule breakdown, semantic boundary copy, and readability improvements each landed without rewriting the whole detail experience.
- Reusing backend-stored `indicator_history` and `rule_breakdown` avoided frontend-only signal invention and kept chart review aligned with screening semantics.

### What Was Hard

- Chart work invited drift. It was constantly tempting to let visual affordances imply new “official” RPS events that did not exist in the approved contract.
- Historical-context usability issues were easy to dismiss as polish even though they directly affected whether the detail page could serve as a real review surface.
- Date handling and chart-library defaults created subtle trust risks; small presentation bugs could make correct data look wrong.

### Lessons Learned

- Explainability boundaries need explicit copy, not just correct data wiring. Users will infer meaning from labels, legends, and layout even when the payload is technically accurate.
- Backend-owned history windows are safer than frontend-owned assumptions for chart workflows that may later expand.
- Review passes remain valuable on chart stories because many failures are semantic or observational rather than pure data bugs.

### Technical Debt / Follow-Up

- The stock-detail page now mixes navigation, watchlist actions, explainability, and chart rendering; future growth may justify decomposing the page into smaller review-focused sections.
- Frontend automation around stock-detail semantic copy is still thin; most contract protection currently lives in backend tests and lint.
- If chart interactivity expands, synchronized-range behavior and mobile readability will need focused regression coverage.

## 2. Next Epic Preparation

### Ready Signals for Epic 4

- The product now has a credible research handoff from screening results into persisted stock-detail review.
- Stock detail can already surface enough context to support later watchlist capture and re-entry workflows.
- RPS semantics are explicit enough that later watchlist and backtest features can rely on them without re-defining chart meaning.

### Risks to Watch

- Watchlist features must preserve route and context continuity instead of creating a disconnected second research surface.
- Detail-page trust language can still drift if future stories add annotations or convenience summaries without checking the approved contract.
- The more workflows link into stock detail, the more important stable route/query semantics become.

### Action Items

- Keep stock-detail responses tied to persisted workflow context whenever a user drills in from another surface.
- Add targeted UI coverage when future stories change stock-detail copy, legends, or date presentation.
- Preserve the distinction between formal screening signals and explanatory chart affordances in all follow-on stories.
